为什么需要 Agentic RL？
=======================

   **适合谁：** 正在评估 LLM Agent 任务 RL 训练框架的用户。

   **你将获得：** 理解为什么 Agentic RL 需要专用训练基础设施，以及 siirl-agentic 如何解决通用 RL 框架的不足。

问题：通用 RL 框架在 Agentic 任务上遇到瓶颈
-------------------------------------------

标准 RL 训练框架（verl、OpenRLHF、TRL）为\ **单轮**\ 文本生成设计：一个 prompt 进去，一个 response 出来，算 reward，更新策略。这对数学推理、摘要和指令跟随效果很好。

但 **Agentic 任务**\ 根本不同：

+---------------+-----------------------------+---------------------------------------------+
| 维度          | 单轮 RL                     | Agentic RL                                  |
+===============+=============================+=============================================+
| 交互模式      | 一个 prompt → 一个 response | 多轮：生成 → 工具调用 → 环境反馈 → 生成 → … |
+---------------+-----------------------------+---------------------------------------------+
| 轨迹长度      | 固定、可预测                | 可变，可达 10-50+ 轮                        |
+---------------+-----------------------------+---------------------------------------------+
| 延迟特征      | 均匀（GPU-bound）           | 高度可变（工具调用：100ms–30s）             |
+---------------+-----------------------------+---------------------------------------------+
| 奖励信号      | 序列末尾                    | 每轮环境奖励 + 最终结果                     |
+---------------+-----------------------------+---------------------------------------------+
| Loss 掩码     | 简单 response 掩码          | 按轮区分模型 token 与环境 token             |
+---------------+-----------------------------+---------------------------------------------+
| 工具管理      | 不涉及                      | 需要提供、扩缩容和负载均衡工具实例          |
+---------------+-----------------------------+---------------------------------------------+

siirl-agentic 的解决方案
------------------------

1. **原生多轮轨迹训练** — ``NaiveFlow`` 状态机（\ ``PENDING → GENERATING → PROCESSING_ENV → TERMINATED``\ ）将工具调用作为一等操作处理，全轨迹跟踪 token 级 log-probabilities 和按轮 loss mask。

2. **异步 MPMD 架构** — Trainer 和 Rollout 作为独立 Ray actor 运行。一个 rollout 等待沙箱响应时，其他 rollout 继续生成。\ ``DataCoordinator`` 缓冲已完成样本供训练消费。

3. **可插拔任务定义** — ``AgentFlow`` 协议（\ ``preprocess → generate → reward``\ ）通过 YAML 配置注入定义新 Agentic 任务。从 SWE 切换到搜索增强 QA 只需改配置文件。

4. **弹性工具基础设施 (AIO)** — AIO 三层调度器（Proxy → ResourcePool → WorkerManager）基于 Holt-Winters 需求预测自动扩缩工具实例。
